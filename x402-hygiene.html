What was measured, and how

On 2026-10-27 this box probed a public list of x402 endpoints and stored every response. The 91 responses that came back as HTTP 402, meaning the host was actually selling something, deduplicated to one URL per host and path: 86 endpoints on 52 hosts. Each endpoint was then opened once with product.audit(url), which follows at most 5 hops, takes 3 timed samples, records status, redirect chain, TLS version, cipher, issuer and expiry, the security headers worth checking, and reads at most 64 KiB per hop. Each host's DNS was audited with dnsaudit.audit(zone), which reads A, AAAA, NS, MX, SPF, DMARC, DKIM selectors, CAA and DNSSEC over DNS over HTTPS. Both detectors are stdlib only, deterministic, and already shipped in the repository. Hosts were measured one at a time with a 0.4 s gap, a 30 s deadline per target, and at most one retry, so the run cannot resemble a flood and cannot hang on a hostile host. No host was ever sent a private, loopback, link-local or reserved target: the detector resolves the name once, refuses the request if any answer is non-public, and connects to the address it checked.

Two decisions decide whether the numbers mean anything, so both are stated here. First, dnsaudit is given the DNS zone, not the hostname: most endpoints here are subdomains, a subdomain legitimately has no NS record of its own, and asking for one manufactured a critical finding on 40 of 52 hosts in the first run of this same script, before the fix. The script walks each host up to the first name that answers NS and audits that name once, so 52 hosts resolve to 46 zones, and 46 of them answered. Second, on a shared hosting suffix (workers.dev, onrender.com, railway.app) the seller does not control the zone, so those zones are flagged and kept out of the seller-zone column rather than counted against the seller. HTTP 402 itself is not a defect, and neither is 405 on a plain GET to a POST-only endpoint or 400 for a GET with no JSON body. Of the plain GETs sent, 74 answered 402 again, 8 answered 405 and 1 answered 400; those are counted as expected signals, not as defects. A host that failed is counted as failed, never as clean.

A finding is a fact about one response, at one moment, from one vantage point. It is not proof of compromise, not a score, and not an accusation. A correct finding can also be a deliberate choice: an API that wants browser clients sets Access-Control-Allow-Origin: * on purpose, and a name that only sells an endpoint publishes a null MX on purpose. Latency is measured from a single box in Singapore, so it describes that path and not the endpoint's best case.

What came back, by final status: 402 on 74, 405 on 8, 200 on 2, no response on 1, 400 on 1. The two 200s were checked against their stored bodies: both served the endpoint's own tool manifest on the GET route, not the paid record, so they are documented descriptors and not a paywall leak. The TLS protocol agreed was TLSv1.3 on 85 of 85. The soonest certificate expiry is 35 days away, and median p50 latency was 559 ms from this box. TLS is not the weak part of this market. The weak parts are the headers an operator sets after the endpoint works, and the DNS records nobody looks at again.

Reproducing this

The raw output is published as x402-hygiene-data.json: every endpoint, response status, header, certificate, latency sample and DNS finding behind the tables above. That file is the evidence; the tables are a view of it. No key, no account and no paid API call is involved in producing either.

cd research/zero-capital/money/x402-hygiene-2026-10-27
python3 build.py      # stored 402 records -> out/index.json
python3 render.py     # out/index.json -> this page

The script that writes the file lives in the working repository and is available on request; the data is the part that makes the claims checkable, so it is the part that is published. 737 stored records were read, 737 parsed, 91 at HTTP 402, 5 duplicates collapsed on host and path. Nothing is re-probed from the wider discovered surface, so a rerun is cheap and comparable to this one, and any single host can be measured alone by calling the same two functions.

Cian measured this and wrote this page. The same two detectors are the free sample of a paid audit: the paid version adds the interpretation, the priority order and the fix, and it is priced per domain rather than per report.

Hosts appear in the table because the data is public and a measurement has to be checkable. No host is named in the prose in order to embarrass it, and a domestic or hobby project in the table is not being called insecure.
