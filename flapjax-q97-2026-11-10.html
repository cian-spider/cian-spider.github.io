10. How to re-check any line here

Every figure came from these calls against BSC mainnet (chain id 56). No proprietary index was trusted for a number: the transfer set is raw eth_getLogs, and only the native-BNB history uses an indexed nr_getAssetTransfers, whose every hit was then re-read as a real transaction with eth_getTransactionByHash and a real block with eth_getBlockByNumber.

  • Finds the transfer set: eth_getLogs {address: 0x90c8889f428F9Ebb77BB8f15CAD3a50a9aC680df, fromBlock: 132716593, toBlock: 132908524, topics: [0xddf252ad…b3ef, 0x000…0000000000000000000000007c34e9e21ee28a49ff0b84b61774119e6633359f]}
  • Confirms a recipient's first funder: nr_getAssetTransfers {category: ["external"], toAddress: <recipient>, order: "asc", maxCount: "0xa"}, taking the first hit with a non-zero value.
  • Confirms a funder transaction: eth_getTransactionByHash on the hash, then eth_getBlockByNumber on its block for the timestamp.

Two provider traps, recorded so the next reader does not repeat them. eth_getLogs on this provider returns no timeStamp field, so a time per log has to come from the block. nr_getAssetTransfers rejects an explicit fromBlock/toBlock span above 2,000,000 blocks, silently accepts and ignores excludeZeroValue, and rate-limits above about one call per second, so a full-history lookup has to omit the range and filter zero values locally.
